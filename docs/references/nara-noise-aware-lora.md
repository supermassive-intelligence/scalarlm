# NaRA: Noise-Aware LoRA for Parameter-Efficient Fine-Tuning of Diffusion LLMs

## Note — why it's here

**Search query:** `LoRA fine-tuning diffusion large language model LLaDA Dream discrete diffusion parameters rank`

**Most directly relevant paper we found.** Two reasons:

1. **It benchmarks our exact model.** The paper's comparison adapts *DiffusionGemma-26B*
   with LoRA and reports the recipe: **rank-64 updates (α=128) on the attention and
   shared-MLP projections, with the 128 experts, the router, and the vision tower frozen.**
   This **independently corroborates our whole ADR-0007 design** (decoder-side, freeze
   router+experts, the always-on dense/shared MLP carries the adaptation) — but at **4× our
   rank and 4× our alpha** (we run r16/α32). Note the tension with our results: our Run #9
   raised rank to r32 and it got *worse* (7/32), pointing at decoding rather than capacity.
2. **It argues static LoRA is structurally wrong for dLLMs** — a noise-agnostic low-rank
   update applied across the whole denoising trajectory "yields negligible improvement at
   high noise levels." This is the one credible *training-side* upgrade for our recipe:
   condition the low-rank update on the noise level `t` (which we already sample as
   `t ~ U(eps,1)` in `diffusion_corruption.py`).

**Extracted hyperparameters (from arXiv HTML, 2605.29716v1):**
- rank `r`: 32 default; ablated `r ∈ {8, 16, 32, 64}` (also r=40 to rule out param-scale)
- NaRA scaling factor `η`: 0.1 default (ablated 1.0 / 0.1 / 0.01)
- trainable params: LoRA ≈0.417% of base; NaRA ≈0.425% (<0.01% over LoRA)
- targeted modules: attention Q/K/V/O
- epochs: 10 (math), 1 (code, commonsense); 128 val samples; loss every 64 steps; 3 seeds
- **not stated in source:** LoRA alpha, dropout, learning rate (for the LLaDA runs)
- backbones: LLaDA-8B-Base/Instruct (+ SDXL for an image-diffusion DreamBooth sanity check)
- mechanism: noise-dependent core `ΔW(λ) = B·C(λ)·A`, `C(λ) = I_r + η·F_φ(e_λ)`,
  `F_φ` = shared hypernetwork on Gaussian-Fourier noise embedding; init `C(λ)=I` so early
  gradients match standard LoRA.
- results: commonsense avg 84.09% vs LoRA 80.18% (Instruct); math 80.89 vs 80.07; code
  pass@1 39.32 vs 38.32.

## Raw material (verbatim)

**Title:** NaRA: Noise-Aware LoRA for Parameter-Efficient Fine-Tuning of Diffusion LLMs
**Authors:** Shuaidi Wang, Zhan Zhuang, Ruping Huang, Yu Zhang
**Submitted:** 28 May 2026 · cs.AI
**arXiv:** https://arxiv.org/abs/2605.29716 · HTML: https://arxiv.org/html/2605.29716v1

> Diffusion Large Language Models (dLLMs) have emerged as a promising non-autoregressive
> generative paradigm. Given the prohibitive computational cost of full fine-tuning,
> Parameter-Efficient Fine-Tuning (PEFT) has become the standard approach. However, existing
> PEFT methods (e.g., LoRA), originally tailored for autoregressive models, rely on static
> parameters that are agnostic to the noise level. Consequently, they ignore the intrinsic
> dynamics of the diffusion process, where input distributions and generation difficulty
> shift significantly along the denoising trajectory, rendering them suboptimal for dLLMs. To
> address this, we propose Noise-aware Low-Rank Adaptation (NaRA), which introduces a low-rank
> core matrix generated by a lightweight, globally shared hypernetwork conditioned on the
> noise level. This design enables the update matrices to vary continuously along the
> diffusion process while keeping parameter and latency overhead negligible. We provide a
> theoretical justification for the proposed NaRA framework and empirically demonstrate
> consistent improvements over noise-agnostic baselines across commonsense reasoning,
> mathematical reasoning, and code generation benchmarks. Our code is available.

## Code map — where NaRA-style fine-tuning lives in the repo

Repo: https://github.com/generaldi/NaRA (cloned 2026-07-17, commit `b6cfb0a`
"Fix NARA-only release"). The repo is the **LLaDA-8B** experiments; there is **no
DiffusionGemma config shipped** — the paper's DiffusionGemma-26B r64/α128 numbers were a
separate benchmark. The released fine-tuning is attention-only, `r_ab=32`.

### The method — `nara/tuners/nara.py` (~1100 lines, self-contained)

LoRA's static `ΔW = B·A` becomes the noise-conditioned `ΔW(λ) = B·C(λ)·A`:

- **`NARAMapper`** — the shared hypernetwork: `Linear→SiLU→Linear→SiLU→Linear` emitting an
  `r×r` core matrix. `init_c="zero_last"` zeros the final layer so `C` starts at 0 and, via
  the residual `Ceff = c_scale·C(λ) + I`, **early gradients equal plain LoRA**.
- **`GaussianFourierProjection` / `MLPEmbedding` / `RawEmbedding`** — noise-level `λ`
  embeddings feeding the mapper.
- **`NARALinear.forward`** (~line 1052) — the adapter math:
  `delta = ((dropout(x) @ Aᵀ) @ Ceff) @ Bᵀ * scale`, with `Ceff` read from a per-layer cache.
- **`NARAModel`** — `set_noise_level`/`set_context_state`, `_precompute_c_matrices` (computes
  one **globally-shared** `Ceff` per current λ, broadcast to all layers), `_find_and_replace`
  (injects `NARALinear`), and **`set_training_stage`**:
  - **Stage 1** — train `A`/`B` only; mapper + embeddings frozen; `C ≡ Identity` (plain LoRA warm-up).
  - **Stage 2** — unfreeze mapper + embeddings; `C(λ)` active (the noise-aware phase).
- **`NARAConfig`** — knobs: `r_ab`, `fnn_hidden_size_1/2`, `init_c`, `c_scale` (= paper's η),
  `input_mode` (`nl`/`nd`/`both`/`constant`), `direct_noise_level`, `density_radius`.

### The noise-aware wiring — the actual per-step diff (small; this is the port surface)

- **`utils/loss.py`** — `compute_original_llada_loss`, the `if finetuning_type == NARA:` branch
  (~lines 101–140): derives the step's noise level from the mask ratio
  (`calculated_nl = ratios` when `direct_noise_level=True`, else `mean(masked_indices)`), then
  calls `forward_with_noise_level(...)` **before** the masked cross-entropy. Plain-LoRA path is
  just `denoiser(noisy_batch).logits`.
- **`utils/util.py`** — `forward_with_noise_level` (line 147) calls `set_context_state(noise_level=…)`
  to push λ into the C-cache before the forward; `random_forward_process` (line 7) is the LLaDA
  masking that produces those ratios.
- **`train.py`** — branches on `config.finetuning_method` (`LORA` vs `NARA`) and drives the
  two-stage schedule (`set_training_stage(1)` → `(2)`, ~lines 401–419).

### Relevance to our stack

The port surface is small: we already sample `t ~ U(eps,1)` in `diffusion_corruption.py`,
which is exactly the `λ` NaRA feeds to the mapper (their `direct_noise_level` uses the mask
ratio as λ). Adopting it would mean vendoring `nara.py`'s adapter + adding a loss-side branch
that calls `set_context_state(noise_level=t)` before the canvas forward — replacing their
LLaDA masking/PeftModel with our canvas corruption + PEFT. Note two divergences from the paper
we'd have to decide on: (1) the released recipe adapts **attention only**, whereas the paper's
DiffusionGemma recipe (and our ADR-0007 design) also adapts the dense/shared MLP; (2) `C(λ)` is
**globally shared across layers**, not per-layer.
